# Deployment

This project can be deployed with the Vite frontend on Vercel and the Express/Socket.IO API on Render. MongoDB Atlas, Cloudinary, and Resend provide the production database, image uploads, and verification email.

## 1. Prepare external services

- Create a MongoDB Atlas database and allow connections from Render. Use its application connection string for `MONGO_URI`.
- Create a Cloudinary account and collect the cloud name, API key, and API secret.
- Set up a Resend account and verify the sending domain/address used for `MAIL_FROM`.
- If enabling subscriptions, create Razorpay API keys. Use test keys until payment flows are ready for production.

Never commit secrets or put server-only secrets in Vercel's `VITE_*` variables.

## 2. Deploy the API on Render

1. Push this repository to a Git provider supported by Render.
2. In Render, create a Blueprint from the repository. Render will read [`render.yaml`](./render.yaml) and create the `connectly-api` web service.
3. Set the prompted environment variables in Render. `JWT_SECRET` is generated by the Blueprint. Set `CLIENT_URL` initially to the Vercel production URL once it is known; multiple allowed frontend origins can be comma-separated.
4. After the first deployment, check `https://<render-service>.onrender.com/api/health`; it should return JSON with status `OK`.

The remaining API settings are feature-specific but needed for full functionality:

| Variable | Purpose |
| --- | --- |
| `MONGO_URI` | MongoDB Atlas connection string |
| `JWT_SECRET` | Signing and verifying login tokens; generated by Render |
| `CLIENT_URL` | Allowed frontend origin(s), comma-separated if needed |
| `CLOUDINARY_CLOUD_NAME` | Cloudinary account cloud name |
| `CLOUDINARY_API_KEY` | Cloudinary API key |
| `CLOUDINARY_API_SECRET` | Cloudinary API secret |
| `RESEND_API_KEY` | Sending verification and password-reset emails |
| `MAIL_FROM` | Verified sender address, for example `Connectly <noreply@example.com>` |
| `RAZORPAY_KEY_ID` | Razorpay key ID (optional until payments are enabled) |
| `RAZORPAY_KEY_SECRET` | Razorpay secret (optional until payments are enabled) |

In production, OTP email delivery requires both `RESEND_API_KEY` and `MAIL_FROM`. Image uploads require valid Cloudinary credentials.

## 3. Deploy the frontend on Vercel

1. Import the same repository into Vercel.
2. Set the **Root Directory** to `client`. Vercel detects Vite; the build command is `npm run build` and the output directory is `dist`.
3. Add these Vercel environment variables for the Production environment (use the Render service URL without a trailing slash):

   | Variable | Example |
   | --- | --- |
   | `VITE_API_URL` | `https://<render-service>.onrender.com/api` |
   | `VITE_API_ORIGIN` | `https://<render-service>.onrender.com` |
   | `VITE_SOCKET_URL` | `https://<render-service>.onrender.com` |
   | `VITE_RAZORPAY_KEY_ID` | The matching Razorpay key ID, if payments are enabled |
   | `VITE_CLOUDINARY_UPLOAD_PRESET` | Optional unsigned upload preset, only if required by the Cloudinary account |

4. Deploy (or redeploy after adding variables). [`client/vercel.json`](./client/vercel.json) rewrites frontend routes to the Vite entry page so direct navigation and refreshes work.
5. Copy the Vercel production origin into Render's `CLIENT_URL` value and redeploy the API.

Vite variables are embedded in the frontend build, so changes to them require a new Vercel deployment. The Razorpay key ID is public-facing; never add the Razorpay secret or Cloudinary API secret to Vercel.

## 4. Verify

- Open the Vercel site and test registration, email verification, login, profile photo upload, chat, and any enabled payment flow.
- Check Render logs if API requests, email delivery, uploads, or Socket.IO connections fail.
- Ensure Atlas network access permits the Render service and that `CLIENT_URL` exactly matches the frontend origin, including `https://` and excluding a trailing slash.
